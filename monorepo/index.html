npm v12 Monorepo Migration: Workspaces, Script Allowlists, Git Dependencies

Monorepos have unique pain in npm v12. Each workspace needs its own script allowlist — the root doesn't propagate. Git dependencies are common for cross-package references. And the root .npmrc doesn't cascade the way you'd expect. Here's how to migrate a monorepo without breaking every package at once.

Why Monorepos Hit Harder

P0 Workspace Allowlists Don't Cascade

The biggest monorepo surprise: npm approve-scripts <pkg> in the root does not apply to workspaces. Each workspace is an independent install scope with its own package.json allowlist. If workspace packages/api depends on bcrypt and workspace packages/worker also depends on bcrypt, you must approve it in both workspaces.

P1 Git Dependencies Are Common in Monorepos

Monorepos frequently use git+https:// for pre-release cross-references or internal forks. npm v12 blocks these by default. Even if your direct deps are clean, a transitive dependency might pull in a Git reference — and your entire npm ci fails.

P1 Root .npmrc Doesn't Cascade

Expectation: set allow-git=true in root .npmrc and all workspaces inherit it. Reality: npm workspaces have their own config resolution. The root .npmrc affects root-level operations; each workspace resolves its own effective config.

Workspace Allowlist Migration

Step-by-Step: Approve Scripts Across All Workspaces

  1. Audit all native deps across workspaces.
    npm ls --workspaces --depth=0 2>/dev/null | grep -E '(sharp|bcrypt|esbuild|node-sass|puppeteer)'
  2. For each workspace with native deps:
    cd packages/api && npm approve-scripts bcrypt
  3. Verify allowlist is committed:
    Check package.json in each workspace has "scriptsApproved" field
  4. Test install from root:
    npm ci --workspaces — all native modules should compile
  5. Add smoke tests:
    In CI: node -e "require('bcrypt'); require('sharp');" in each workspace

Automation Script

copy#!/bin/bash
# approve-scripts-workspaces.sh — approve scripts across all workspaces

APPROVE_LIST=("node-gyp" "sharp" "esbuild" "bcrypt")

# Get all workspace directories
WORKSPACES=$(node -e "
  const pkg = require('./package.json');
  if (pkg.workspaces) {
    const glob = require('glob'); // or manual list
    pkg.workspaces.forEach(pattern => {
      // Simple pattern match — expand as needed for glob
      console.log(pattern.replace('/*', ''));
    });
  }
")

for ws in $WORKSPACES; do
  echo "=== Workspace: $ws ==="
  cd "$ws"
  for pkg in "${APPROVE_LIST[@]}"; do
    if node -e "try{require('$pkg')}catch(e){process.exit(1)}" 2>/dev/null; then
      npm approve-scripts "$pkg" 2>/dev/null && echo "  ✓ approved $pkg" || echo "  − $pkg not in deps"
    fi
  done
  cd - > /dev/null
done

echo "Done. Run: git diff --stat to review allowlist changes"

Git Dependency Alternatives

npm v12 blocks Git deps. In monorepos, these are often used for cross-package references during development. Here are your migration paths, best to worst:

Best: npm Workspaces Protocol (workspace:*)

Replace "@myorg/api": "git+https://github.com/myorg/repo.git#feat-branch" with "@myorg/api": "workspace:*". Only works for packages within the same monorepo listed in root workspaces config. Zero overhead, no extra tooling.

Good: Verdaccio (Local Registry Mirror)

Run a local npm registry that mirrors your private packages. Git deps become standard registry deps. Verdaccio runs in Docker, caches upstream, and lets you publish pre-release versions of workspace packages. docker run -d -p 4873:4873 verdaccio/verdaccio.

OK: file: Dependencies (Same Repo Only)

Replace "@myorg/api": "git+https://..." with "@myorg/api": "file:../packages/api". Works for local development, but the dependency is resolved as a symlink — the resolved version isn't locked in package-lock.json.

Short-Term: --allow-git Flag

Add allow-git=true to .npmrc. This buys time, but npm's security team explicitly recommends against long-term reliance. Use this while you migrate Git deps to one of the above solutions.

lerna / nx Integration

lerna + npm v12

Impact: lerna delegates to npm for install. When lerna runs npm install in each package directory, npm v12 blocks scripts. Fix: Approve scripts in each package before lerna bootstrap. Or set "npmClient": "npm" in lerna.json and ensure workspaces are configured for npm v12.

nx + npm v12

Impact: nx uses the system npm. When nx orchestrates tasks across packages, native module compilation can fail silently. Fix: Add a pre-task hook in nx.json that runs npm approve-scripts for known native deps before any build task. Or migrate script approvals to package.json and commit them — nx then picks up the approved state automatically.

Common Monorepo Failures

"Root allow-scripts doesn't apply to workspaces"

You approved sharp at the monorepo root, but packages/image-service still fails to compile. This is by design — workspaces are independent install scopes. Run npm approve-scripts sharp from within each workspace that depends on it.

"Transitive Git dep from workspace breaks whole install"

Workspace A has a clean dependency on package B, but B's package-lock.json references a Git dep. npm v12 blocks it and the entire npm ci --workspaces fails. Audit with: grep -r 'git+https://' packages/*/package-lock.json. Fix: migrate transitive Git deps to registry versions, or add allow-git=true as temporary escape hatch.

"npm ls shows missing packages after v12 upgrade"

Packages appear in package.json but npm ls doesn't show them. This happens when a workspace's native module script was blocked — the package is "installed" (files downloaded) but the native binary doesn't exist. npm ls shows what compiled successfully. Fix: approve and rebuild.

FAQ

How to approve scripts in all workspaces at once?

There's no single command yet. Use a shell loop: for ws in packages/*; do cd $ws && npm approve-scripts <pkg> && cd -; done. Or use the automation script in the guide above. npm's workspace support for approve-scripts --workspaces is expected in a future minor version.

Monorepo root .npmrc allow-git doesn't cascade to workspaces

npm workspaces resolve config independently. Put an .npmrc in each workspace directory, or set the config at install time: npm ci --workspaces --allow-git. The root .npmrc affects root operations only — workspace-level operations use the workspace's own config resolution.

Can I use npm workspaces with v12 script allowlists?

Yes. npm workspaces and script allowlists are independent systems. Workspaces manage package resolution and linking; allowlists manage script execution. You just need to approve scripts in each workspace individually — the workspace mechanism itself is unaffected by v12's changes.

lerna bootstrap fails on npm v12

lerna runs npm install in each package, and npm v12 blocks native module scripts. Fix: approve scripts in each package before running lerna bootstrap. Or use lerna exec -- npm approve-scripts <pkg> to approve across all packages in one command.

How to find all Git deps across a monorepo?

Run: grep -r 'git+https://' packages/*/package.json packages/*/package-lock.json 2>/dev/null. For transitive Git deps (harder to find): find . -name 'package-lock.json' -exec grep -l 'git+https://' {} \;. This catches Git deps pulled in by dependencies you don't directly control.

Should I use npm workspaces or pnpm for monorepos with npm v12?

Both work. pnpm already has per-package script approval (onlyBuiltDependencies) and is slightly ahead on this front. But if you're already on npm workspaces, migrating to pnpm just for v12 is overkill — the workspace approval script above handles it. If you're considering a monorepo tool switch anyway, pnpm's security posture is closer to npm v12's philosophy.
